1 · Project & target

Name your project. The target URL is taken from your recording (you can override it here). Login is driven by the recording; for multi-user load, upload a credentials CSV below with several accounts.

1 · Upload your BlazeMeter recording

APEA works entirely from your recording — JMeter .jmx, Taurus/BlazeMeter .yaml/.yml, or .har. It reads the journey, auto-correlates dynamic values, and tells you exactly what data to upload.

1b · Or — crawl & record with a headless browser (no recording needed)

No recording to upload? Give APEA a target URL above and it drives a real headless browser (Playwright) through the site itself — home page, search, login (if you give credentials below), add a product to cart, view the cart — and captures the actual requests it makes along the way, the same way an uploaded recording would. It stops at add-to-cart: checkout and payment forms vary too much across sites to drive blindly, so that part still benefits from an uploaded recording. Requires Playwright on the server (pip install playwright && playwright install chromium) — otherwise this just tells you so instead of failing silently.

2 · Choose a test — in plain English

Pick a test type and APEA sets the users, ramp-up, duration, pacing and pass/fail criteria — or start from a Performance Test Plan and it fills these in for you.

APEA reads the plan and recommends the test types it describes — with users, duration, ramp-up, think time, SLA, objectives and scenarios — then pre-fills the fields below (all editable). It does not auto-run anything. No API key needed.

Think time & SLA — auto-filled from an uploaded test plan; edit to override.

Replays the recorded requests exactly as captured, in one session, with the recorded headers/token — no parameterization, correlation, or auto-heal. Behaves like JMeter running the raw recording (good for a quick first pass; brittle across many iterations). Leave off for the robust AI-correlated run.

Payment token & CAPTCHA (rarely needed)
{{column}} reads that column from each user’s own row. Add a default after a pipe — {{card_cvv|123}} — for a value that is the same for the whole pool, and you can drop the column entirely. A placeholder with no default and no value stops the run rather than paying by some other method.
💳 Real-browser payment track (Playwright) — drive real card iframes

Runs a small pool of REAL browsers alongside the load test to complete a hosted card payment (Stripe / CyberSource) that HTTP replay can't. Requires Playwright (run setup-browser-track.bat once). Leave Browser VUs at 0 to keep it off — the normal HTTP load test is unchanged.

🧪 Intelligent Test Data Generator

Generates realistic, validated data for the selected test — customers, products (distributed so users don't all buy one SKU), addresses, payments and search terms — sized from the plan. The result becomes this run's data set, and throughput / test type / users are set for you. Analyze a recording first (optionally upload a test plan above).

When a run fails, Claude reads the actual failures, fixes the script
        (correlation, headers, REST prefix, payment method, address fields…) and regenerates
        it. Broken-script failures are re-run automatically; a timed run that produced traffic
        is healed for the next run so it still stops at its duration.
