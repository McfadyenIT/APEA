# Parametrization vs. Correlation — Detection Catalog

Two buckets, one question to ask about every dynamic-looking value you
find: **does this need to vary because it's test data (parametrization), or
does it need to be captured because the server generated it mid-session
(correlation)?** Getting a value into the wrong bucket is the single most
common cause of a load test that passes once and then fails on every
subsequent iteration.

A quick test: if you deleted this value and asked a human tester "what
would you type here?", it's parametrization (a username, a search term, a
quantity). If you asked a human tester "where did this come from?" and the
honest answer is "the previous page gave it to me," it's correlation (a
cart ID, a CSRF token, a session cookie).

## Parametrization candidates (supply from test data)

| Field | Typical pattern | Recommended CSV column |
|---|---|---|
| Username / email | form field `login[username]`, `email` | `username` |
| Password | form field `login[password]`, `password` | `password` |
| SKU / product ID | query param or path segment on PDP/cart-add calls, repeats across users but should vary | `sku` |
| Quantity | body field `qty`, `quantity` | `quantity` |
| Search keyword | query param `q`, `keyword`, `search_query` | `search_keyword` |
| Category / filter | query param `cat`, `category_id` | `category` |
| Shipping / billing address | body fields `street`, `city`, `postcode`, `country_id` | `address_*` |
| Coupon / promo code | body field `coupon_code`, `promo` | `coupon_code` |
| Payment method selection | body field `payment[method]` | `payment_method` |

If the recording only shows one literal example of any of these, that's
still parametrization — flag it as "single sample observed, needs more
variety before load testing" rather than treating it as static.

## Correlation candidates (extract from a prior response)

| Field | Where it's usually generated | Extraction strategy |
|---|---|---|
| `form_key` (Magento) | HTML of any page | Regex against response HTML: `form_key.*?value="(.+?)"` |
| CSRF / `_token` | Login or page-load response | Regex or JSON path from the response immediately before use |
| `quoteId` / `cartId` | Cart-creation call | JSON path from that call's response body |
| Session cookie (`PHPSESSID`, `JSESSIONID`) | Login response `Set-Cookie` header | Read from `Set-Cookie` on login, replay as `Cookie` on subsequent calls |
| Bearer / OAuth token | Login or token-endpoint response | JSON path from the token response, e.g. `$.access_token` |
| `orderId` / order number | Place-order / checkout success response | JSON path or HTML pattern, extract **after** confirming the success page actually rendered |
| Any numeric/UUID ID that first appears in a response and reappears in a later request's path or body | Whichever call created it | JSON path or regex from that creating response |

A practical tell: if the same field has the *same* value across every
occurrence of a request in the recording, it's more likely a parametrization
candidate that just wasn't varied during recording. If it's *different*
each time a multi-step flow repeats, it's almost certainly correlation.

## Platform-specific notes

**Magento / Adobe Commerce** — expect `form_key` on nearly every POST,
`quoteId` through the cart lifecycle, and REST/GraphQL calls under
`/rest/` or `/graphql` that may carry a separate bearer token from the
storefront session.

**Salesforce Commerce Cloud** — session identified via
`dwsid`/`dwsecuretoken` cookies; basket ID appears after the first
add-to-cart and must be carried through checkout.

**Mirakl** — API-key or OAuth-based auth on marketplace operator calls;
offer/order IDs are correlation candidates generated by prior create calls.

**Generic REST / GraphQL** — look for a token endpoint response fanning out
into an `Authorization: Bearer` header on everything after it; GraphQL
`variables` blocks in the request body are a fast way to spot both
parametrization fields (user-supplied variables) and correlation fields
(IDs echoed back from a previous mutation's response).
